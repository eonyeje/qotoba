Plan · part 3 of 5 · first-level task outline · 5 November 2026

Qotoba Workstreams

Ten workstreams and 78 first-level tasks. Each task is sized, placed in a phase, tied to what it depends on, and given the proof that makes it done. This is the outline the Workbench's lanes and tasks are created from; the units under each task are planned by the session that takes it.

How to read this

ID
WSn-m, the workstream and its task. The Workbench allocates register IDs when tasks are created; these are plan references only.
Size
S under 20 session-hours · M 20 to 60 · L 60 to 150 · XL over 150, which means the task is split into lanes before it starts.
Phase
A Foundations · B First light · C Qotoba builds Qotoba · D Dope · E Production apps · F Platform depth, as on the programme page.
Proof
What turns the task green: a suite, a gate, a measurement or a packet. "Done means checked" (W14). A task with no proof is not a task.
Lane
Designed lanes need the owner's design approval before building; autonomous lanes run against their gates. The default is designed for WS1 to WS3, autonomous for WS6 and WS7 once their first slice lands.

Workstream 1

Language core

10 tasks · phases A to F · about 700 session-hours

The compiler's middle: everything between the syntax records the parser already produces and the Qotoba Core the emitters consume. Phases 5 to 8 of the language's own plan, then the later runtime phases.

WS1-2Binder. Phase 5: symbols, scopes, types resolved on the new tree, with the agreed API. Module versions so a change rebinds only what changed.WS1-1A · LBinder suite over the full corpus; rebind time per edit under 50 ms on the 12,890-character test program.

Designed so the core redesign's constructs map onto it later.WS1-2A · MEvery corpus program lowers to Core and prints; a Core-level validator finds no unbound names.
WS1-5Intent framework.
